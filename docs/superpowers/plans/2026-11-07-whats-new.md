# What's New (Proactive GA, Part 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `whats_new` tool (MCP, both transports, and CLI) that tells the person what arrived in GA since they last looked, then the items worth reviewing: recent out-of-range labs, new medications with their FDA label sections, vaccine series follow-ups, and Epic health maintenance items now due.

**Architecture:** The engine stamps an arrival instant on every record it creates. `src/whats-new.ts` finds records that arrived since the stored "last seen" time (coarse `_lastUpdated` search, exact arrival filter in code), tallies them, and builds review items from existing code (`summarizeLabs` grouping, `listRows` currency, `vaccineGaps`). `src/drug-labels.ts` fetches and caches FDA label sections by RxNorm code. The tool registers in `src/mcp.ts`, so chat apps get it too.

**Tech Stack:** Node 26 strip-only TypeScript, Medplum client, vitest, openFDA and RxNav over `fetch`.

**Spec:** `docs/superpowers/specs/2026-11-07-proactive-ga-design.md` (Part 1; "Decisions from the builder check" 1, 2, 6, 10).

## Global Constraints

- Node 26 type stripping: no enums, namespaces or parameter properties; `.ts` import suffixes.
- Only RxNorm codes leave the machine (openFDA, RxNav). Never names from the record, never values or dates.
- No PHI in the repo: tests use synthetic records; integration tests run in the long-lived `ga-test` project (`tests/integration/helpers.ts` `testProject`), never the user's patient.
- Every review item cites its evidence: record date, value, source file name (`basename(meta.source)`), record id.
- The medication check is quoted label text with the label's `effective_time` and `set_id`, ending with: "From the FDA label; not a full interaction screen. Ask your pharmacist."
- Tool results stay under the remote 150k cap (`fit` in `src/labs.ts`; label sections trimmed).
- Unit tests: `npm test`; integration: `npm run test:int`. Both green before each commit.
- Each task ends with a ponytail pass (`/ponytail:ponytail` on the task's diff) before its commit is final. **[user]**

## Review Focus

1. **A re-import or daily sync must not make old records "new".** Updates, merges, last-seen bumps and concept re-coding keep the original arrival instant. (Task 1 test.)
2. **Records from before this feature have no arrival marker** and must not flood the first run. They count as "before tracking". (Task 2 test.)
3. **A lab without a range or flag is never judged**; an out-of-range lab older than 12 months (clinical date) is tallied but not a review item. (Task 3 test.)
4. **openFDA down, rate-limited (429) or no label** returns `{status: 'unavailable' | 'no label'}` for that drug; the rest of `whats_new` still returns. (Task 4 test.)
5. **`whats_new` without `markSeen` never moves the stored time**; `since` given explicitly never moves it either. (Task 5 test.)

### Task 2: Arrivals since, tally and last-seen state

**Files:**
- Create: `src/whats-new.ts`
- Test: `tests/whats-new.test.ts`

**Interfaces:**
- Consumes: `arrivedAt` (Task 1).
- Produces:
  - `export type Kind = 'lab results' | 'vital signs' | 'Apple Health readings' | 'medications' | 'problems' | 'allergies' | 'vaccines' | 'procedures' | 'visits' | 'notes and messages' | 'other'`
  - `export function kindOf(r: Resource): Kind`: Observation by tag `src-apple-health` → Apple, category `vital-signs` → vital signs, else lab results (category laboratory, extracted-by-llm or none); MedicationStatement/MedicationRequest → medications; Condition → problems; AllergyIntolerance → allergies; Immunization → vaccines; Procedure → procedures; Encounter → visits; DocumentReference/Communication → notes and messages; else other.
  - `export function clinicalDate(r: Resource): string | undefined` (YYYY-MM-DD from effective/occurrence/onset/recorded/authored/period.start/date/sent/issued, first present).
  - `export function tally(arrived: Resource[], asOf: string): { total: number; historical: number; byKind: Partial<Record<Kind, number>>; sources: string[] }`: historical = clinical date more than 365 days before `asOf`; sources = distinct `src-*` tag labels (as `SOURCES` in `src/health.ts`: move that list to `whats-new.ts` and import it back into `health.ts`) plus portal source keys from `urn:ga-server:id:smart:<key>` identifiers.
  - `export async function arrivedSince(client: MedplumClient, patientId: string, since: string): Promise<Resource[]>`: per type in `kindOf`'s list, `_lastUpdated=ge<since>`, patient compartment param (`subject` or `patient`), `_sort=_lastUpdated`, `_count=1000`, cursor pages (`client.searchResourcePages`); keep those with `arrivedAt(r) >= since`. Records without `ARRIVED` are "before tracking" and never returned.
  - `export function readLastSeen(dir?: string): string | undefined` / `export function writeLastSeen(at: string, dir?: string): void`: `.ga/whats-new.json` `{ "lastSeen": "<ISO>" }`, dir default `dirname(defaultConfigPath())`, written atomically (`writeAtomic` from `src/smart/store.ts` or the file's existing helper), mode 0600.

- [ ] **Step 1: Failing tests** (pure, no server): `kindOf` for each branch; `clinicalDate` precedence; `tally` with synthetic records on both sides of the 365-day line (`asOf: '2026-11-07'`, a lab dated `2025-11-06` is historical, `2025-11-07` is recent); `readLastSeen` on a missing file → `undefined`, round trip through a temp dir.
- [ ] **Step 2:** Run → fail. **Step 3:** Implement. **Step 4:** `npm test` → pass.
- [ ] **Step 5: Integration test** `tests/integration/whats-new.test.ts` `'arrivedSince returns created records, not old or unmarked ones'`: in the `ga-test` project create one record without `ARRIVED` (direct `createResource`) and import one through `importResources`; `arrivedSince(since = test start)` returns only the imported one. `npm run test:int -- whats-new` → pass.
- [ ] **Step 6:** Ponytail pass, commit `feat: whats_new arrivals, tally and last-seen state`.

### Task 3: Review items

**Files:**
- Modify: `src/labs.ts` (extract grouping), `src/whats-new.ts`
- Test: `tests/labs.test.ts` (unchanged behaviour), `tests/whats-new.test.ts`

**Interfaces:**
- Produces:
  - `export function groupLabs(obs: Observation[]): Observation[][]` in `src/labs.ts`: the groups `summarizeLabs` builds today, each newest first; `summarizeLabs` becomes `groupLabs(obs).map(...)` with identical output (existing `labs.test.ts` passes untouched).
  - `export type ReviewItem = { kind: 'lab' | 'new medication' | 'medication status' | 'problem status' | 'vaccine follow-up' | 'health maintenance'; title: string; date?: string; detail: Record<string, unknown>; source?: string; id?: string }`
  - `export function labItems(arrived: Observation[], allLabs: Observation[], asOf: string): ReviewItem[]`: arrived labs with `highLow(o)` set and clinical date within 365 days of `asOf`; detail `{ value, range, flag, previous: { date, value } | undefined }` where previous is the next older dated result in the same `groupLabs` group. Newest first.
  - `export function medicationItems(arrived: Resource[], all: Resource[], since: string): ReviewItem[]`: a medication is new when no record in `all` with the same RxNorm code (trusted codings, `trusted` from `src/concept-apply.ts`) or, uncoded, the same normalised name (`concept` from `src/lists.ts`, lower-cased, spaces collapsed) arrived before `since`. Detail `{ rxnorm?: string, status }`.
  - `export async function statusItems(client, patientId, since): Promise<ReviewItem[]>`: MedicationStatement, MedicationRequest, Condition updated since `since` (`_lastUpdated`), whose `status`/`clinicalStatus` differs from their last `_history` version before `since`. Detail `{ from, to }`.
  - `export function followUpItems(vaccines: Awaited<ReturnType<typeof vaccineGaps>>, hm: Observation[], asOf: string, birthDate?: string): ReviewItem[]`: vaccines with status `due`/`overdue` and at least one record (a started series); Epic `Health maintenance: <topic>` Observations whose status (`valueString`) is `Overdue` or `Due`, or whose Next due component date is ≤ `asOf`; a Next due date before `birthDate` is dropped from detail (status only). Detail carries `asOfExport` = the record's `urn:ga-server:ext:source-date`.

- [ ] **Step 1: Failing tests** in `tests/whats-new.test.ts` with synthetic records:
  - `labItems`: a new high LDL with an older LDL in the same group → item with `previous`; a new result with no range and no interpretation → no item; a new high result dated 2024 with `asOf` 2026-11-07 → no item.
  - `medicationItems`: same RxNorm arrived earlier from another source → not new; first appearance → new; uncoded, same name different case → not new.
  - `followUpItems`: zoster `due` with 1 record → item; `due` with none → no item; HM `Overdue` with a Next due date before `birthDate` → item whose detail has no due date; HM `Not Due` with Next due tomorrow → no item.
- [ ] **Step 2:** Run → fail. **Step 3:** Implement. **Step 4:** `npm test` → pass, `tests/labs.test.ts` untouched and green.
- [ ] **Step 5: Integration test** `'statusItems sees a medication stopped since'`: create an active MedicationStatement, note `since`, update it to `stopped`; `statusItems` returns `{from: 'active', to: 'stopped'}`. `npm run test:int -- whats-new` → pass.

### Task 4: FDA drug labels

**Files:**
- Create: `src/drug-labels.ts`
- Test: `tests/drug-labels.test.ts`

**Interfaces:**
- Produces:
  - `export type LabelSections = { status: 'ok'; rxcui: string; setId: string; effective: string; title?: string; sections: Partial<Record<'boxed_warning' | 'contraindications' | 'warnings_and_cautions' | 'warnings' | 'drug_interactions' | 'use_in_specific_populations', string>> } | { status: 'no label' | 'unavailable' | 'no code'; rxcui?: string }` ('no code' is used by Task 5 for uncoded medications)
  - `export async function drugLabel(rxcui: string, opts?: { fetch?: typeof fetch; dir?: string; now?: Date }): Promise<LabelSections>`

- [ ] **Step 1: Failing tests** with an injected `fetch` (no network) and a temp cache dir:
  - `'finds the newest label with sections by product code'`: openFDA returns two labels; the one with the later `effective_time` wins; each section is joined text trimmed to 4,000 characters, ending `…` when cut.
  - `'falls back through RxNav related products'`: openFDA returns 404 for the code; RxNav `related.json?tty=SCD+SBD` returns two product codes; the second openFDA query ORs them and succeeds.
  - `'caches for 30 days'`: second call within 30 days makes no fetch; after 31 days (`now`) it fetches again.
  - `'unavailable on network error or 429, no label on empty'`: never throws.
  - `'sends only the code'`: every requested URL matches `/rxcui[:/]"?\d+/` and contains nothing else from the input.
- [ ] **Step 2:** Run → fail.
- [ ] **Step 3:** Implement. openFDA query: `https://api.fda.gov/drug/label.json?search=openfda.rxcui:"<rxcui>"+AND+_exists_:drug_interactions&sort=effective_time:desc&limit=1` (codes OR-ed in parentheses for the fallback, at most 20). Validate `rxcui` against `/^\d{1,10}$/` before any URL is built. Cache file `.ga/labels/<rxcui>.json` with `fetchedAt`; cache `no label` too (30 days), never `unavailable`.
- [ ] **Step 4:** `npm test` → pass.
- [ ] **Step 5:** Ponytail pass, commit `feat: FDA label sections by RxNorm code, cached`.

### Task 5: `whats_new` tool, CLI and docs

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `export async function whatsNew(client, patientId, eps: Promise<Endpoint[]>, opts: { since?: string; markSeen?: boolean; asOf?: string; fetch?: typeof fetch; dir?: string }): Promise<{ since: string; firstRun?: true; tally; items: ReviewItem[]; medicationCheck: { drug: string; label: LabelSections }[]; context: { currentMedications; activeProblems; recentOutOfRange }; note: string }>`
    - `since` = `opts.since` ?? `readLastSeen()` ?? 90 days before `asOf` (`firstRun: true`).
    - `markSeen: true` and no `opts.since` → `writeLastSeen(now)` after the result is built. Otherwise nothing is written.
    - `medicationCheck`: one `drugLabel` per new medication with an RxNorm code; uncoded ones appear as `{ drug, label: { status: 'no code' } }`.
    - `context`: current medications and active problems from `listRows` (current only), `recentOutOfRange` = `labItems` over all labs of the last 365 days (not only arrived).
    - `note` (exact): "From the FDA label; not a full interaction screen. Ask your pharmacist. Report only what the label sections say, quoting the section and the label date."
    - Items ordered: lab, new medication, medication status, problem status, vaccine follow-up, health maintenance; `fit` to 200.
  - MCP tool `whats_new` `{ since?: string (YYYY-MM-DD), markSeen?: boolean }`, `readOnlyHint: false` (it writes the last-seen time), through `warned(...)` like `health_summary`. Description: call at the start of a health conversation when not shown yet in this conversation; answer the person's question first, then offer the summary in one line; pass `markSeen: true` only on the call whose summary you showed.
  - CLI `ga whats-new [--since YYYY-MM-DD]`: prints the JSON; never marks seen.
